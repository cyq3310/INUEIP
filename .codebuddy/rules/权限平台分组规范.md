# 权限平台分组规范（分配权限页的平台页签）

## 适用范围
后台「角色权限 → 分配权限」弹窗中的平台页签，以及 `permission` 表的平台归属（`platform` 列）。
新增任何带权限的功能模块时，都必须按本规范确定其平台归属。

## 判定规则（核心）
**依据「该功能是否开发在 EIP 代码库（`INUEIP`）内」判定：**

| 情况 | 归属 | 页签表现 |
| --- | --- | --- |
| 功能开发在 EIP 代码库内（如 账号管理、角色权限、应用链接、公告管理、门户背景、AI Skill） | `platform = eip` | 归入 **EIP 平台**页签 |
| 独立产品、独立代码库与独立部署（如 知识库 InuWiki，权限码 `kb:*`） | `platform` 取独立键值（如 `kb`） | **独占一个平台页签** |

> 一句话记忆：**在 EIP 代码里开发的归 EIP 平台；独立出去的产品才有自己的页签。**
> 注意：AI Skill 虽名为「平台」，但其代码在 `INUEIP` 内（`backend/app/controller/Skill.php`、`frontend/src/views/admin/AiSkills.vue`），因此归 EIP 平台。

## 当前平台清单
- **EIP 平台（`eip`）**：账号管理、角色权限、应用链接、公告管理、门户背景、AI Skill 管理、Skill 分类。
- **知识库平台（`kb`，InuWiki）**：知识库菜单（`system:kb`）及其下 8 个接口（`kb:article:list/create/update/delete/publish`、`kb:category:manage`、`kb:space:manage`、`kb:media:upload`）。

## 数据模型约定
- 平台归属的唯一数据源是 `permission.platform`；`backend/app/controller/admin/Permission.php` 的 `PLATFORMS` 决定**有哪些页签、叫什么、什么顺序**。
- 结构固定为「平台 → 菜单 → 接口」：菜单顶点 `parent_id = 0` 且自身带 `platform`；接口挂在菜单下（接口继承菜单的平台，无需单独维护 `platform`）。
- 未标记或取值未在 `PLATFORMS` 注册的权限会**回落到 `eip`**，避免权限在界面上丢失。
- 前端**无需改动**：页签由后端返回的 `PermissionPlatform[]` 数据驱动（`frontend/src/views/admin/Roles.vue` 的 `el-tabs`）。

## 新增平台的标准步骤
1. **确定归属**：先按上面的判定规则确认是 `eip` 还是独立键值（如新平台 `xxx`）。
2. **注册页签**：在 `backend/app/controller/admin/Permission.php` 的 `PLATFORMS` 中加入 `'xxx' => '展示名'`（顺序即页签顺序）。
3. **写入数据**：新增迁移（幂等、可回滚）为该模块菜单与接口写入 `platform`；或在 Seeder 中给权限行附 `platform`。
4. **建菜单顶点**：一个 `type=menu`、`parent_id=0`、带 `platform` 的菜单权限，其接口作为子节点挂在其下。
5. **权限 id 分配**：避开已占用段——`1-6/10-16` 账号与角色、`20-24` 应用链接、`30-37` 公告、`40-43` 门户背景、`60-64/70-74/85-89` AI Skill、`75-83` 知识库；新模块继续向后取空闲 id（先查库确认）。
6. **验证**：执行 `php think migrate:run`（PHP 用 `h:\XAMPP\php\php.exe`）后用 SQL 只读核对 `platform` 分布，再到「分配权限」弹窗确认页签。

## 注意事项
- **`platform` 键值一经使用即作为页签 key，不可随意更改**，否则历史角色授权与分组会错位；只可改 `PLATFORMS` 中的展示名。
- **不要在 Seeder 内混用 Phinx `$this->table()->insert()` 与原生 `Db` 更新同一张表**：会互相等待行锁导致 `1205 Lock wait timeout`。批量更新 `platform` 统一放在迁移里。
- 已执行过的迁移**不要回改**，需要调整时新增一条幂等迁移，保持存量库与全新安装结果一致。
- 接口权限补录后若绑定了路由（`backend/route/app.php` 的 `PermissionCheck`），需同步确认相关角色已获授权，避免阻断员工自助操作。
