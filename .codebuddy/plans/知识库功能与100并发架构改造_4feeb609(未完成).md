## 产品概述

在 INUEIP 企业信息门户中新增「知识库」模块，支持图文与大视频（100MB–1GB）内容的发布、检索与在线播放；同时将系统从 Windows XAMPP 开发形态迁移到 Ubuntu 生产形态，使其可承载 **100 人同时操作（峰值并发请求 60–100）**。存储沿用本地磁盘。

## 核心功能

### 一、架构与容量达标（前置）

- 部署形态切换：Ubuntu + Nginx + PHP-FPM + OPcache，替换现有 Apache/mod_php
- 引入 Redis 作为缓存、会话与队列驱动
- 数据库参数调优（关闭调试态 SQL 监听、开启字段缓存、提升连接数）
- 产出 60–100 并发压测报告作为验收依据

### 二、知识库功能

- **分类管理**：树形分类的增删改查、排序、启停
- **知识文章**：富文本正文（复用 wangEditor + HTMLPurifier）、封面图、摘要、草稿/发布/下架状态、浏览量
- **图片支持**：多图上传、自动生成缩略图与封面
- **视频支持**：100MB–1GB 大视频的分片上传、断点续传、服务端异步转码（H.264/AAC + faststart + 封面帧）、在线拖拽播放
- **附件管理**：统一资源表记录类型、路径、大小、时长、转码状态
- **权限控制**：复用现有 RBAC，新增 `knowledge:*` 权限点，菜单级 + 接口级双层校验

### 三、视觉与交互效果

- 门户端：分类导航 + 卡片式知识列表 + 详情页（左侧目录、右侧正文、内嵌视频播放器）
- 后台端：分类树 + 文章表格 + 富文本编辑器 + 带进度条/暂停/续传的上传面板
- 上传过程可视化：分片进度、合并中、转码中、就绪四态流转；断点刷新后可自动续传

## 实现方案

### 一、容量结论：当前架构能否承载 100 人

**结论：现状不能，改造后可以。** 瓶颈不在 ThinkPHP（业务代码仅 39 个 php 文件），而在运行时与视频传输模型。

| 环节 | 现状（实测/代码证据） | 改造后 | 60–100 并发评估 |
| --- | --- | --- | --- |
| PHP 执行 | OPcache 实测 `off`，单请求约 80–150ms | OPcache 开启后降至 15–40ms | `pm.max_children=80` → 理论 QPS 2000+，**余量充足** |
| Web 并发模型 | Apache mod_php，Windows `ThreadsPerChild` 仅数十 | PHP-FPM 进程池 `max_children=80` | **充足** |
| 数据库 | `fields_cache=false` 每请求解析表结构；`trigger_sql=env('APP_DEBUG',true)` 默认开 | `trigger_sql=false`、`fields_cache=true`、`max_connections=300` | **充足** |
| 缓存 | file 驱动，并发下文件锁竞争严重 | Redis | **充足** |
| **大视频传输** | PHP 进程直出 1GB 文件 → 单请求占用 worker 数十秒，并发下线程池瞬间耗尽，**整个门户不可用** | **`X-Accel-Redirect` 交给 Nginx sendfile 零拷贝发送，PHP 只做鉴权** | **关键修复，改造后 PHP 不被占用** |
| 上传 | `post_max_size=40M`、`myconfig.upload.max_size=5MB`、`allowed_ext` 无视频 | 分片上传（5MB/片），**无需把 post_max_size 提到 1GB** | **充足** |
| 带宽/磁盘 | 无规划 | 60 人 × 2Mbps ≈ 120Mbps；1GB × N 极易撑爆磁盘 | **需容量规划与转码压缩** |


**关键设计决策：**

1. **视频字节流绝不经过 PHP**。鉴权通过后返回 `X-Accel-Redirect` 头，由 Nginx `internal` location 用 `sendfile` 直接发文件。这是 60–100 并发能否存活的**唯一决定性设计**。Nginx 对静态文件原生支持 HTTP Range（206），拖拽播放天然可用。
2. **分片上传规避 PHP 上传限制**。5MB/片意味着 `upload_max_filesize=8M`、`post_max_size=10M` 即可，完全不需要放开到 1GB —— 这同时消除了"整个请求体被丢弃"的现有风险（`Skill.php:316-317` 注释已暴露此问题）。
3. **指纹续传不用浏览器全量哈希**。1GB 文件在浏览器算 MD5 会卡死主线程。改为：`/init` 由服务端下发 `uploadId`，前端用 `文件名+大小+lastModified` 作本地键存 `localStorage`；`/check` 扫描分片目录返回已传索引。零额外依赖，续传可靠。
4. **合并与转码必须异步**。200 个分片合并成 1GB 文件是长时间 IO，必须进队列；合并用 `fopen/fread/fwrite` 流式拼接（禁 `file_get_contents`，否则内存爆炸）。
5. **权限复用现有 RBAC**，新增 `knowledge:list/create/update/delete/publish/category` 权限点，沿用 `PermissionCheck` 中间件。
6. **所有环境相关参数仍只写 `backend/config/myconfig.php`**，遵守 `.codebuddy/rules/统一配置与发布规范.md`；`database`/`jwt` 组禁止进 `frontend_public.keys` 白名单。

| 接口 | 方法 | 说明 |

## 实现要点（防回归）

- **`X-Accel-Redirect` 路径必须与 Nginx `internal` location 严格对齐**，且 PHP 侧要用 `realpath` 校验最终文件位于 `upload_root()` 之内，杜绝目录穿越（复用 `common.php:117 move_to_trash()` 已有的越界校验写法）。
- **合并分片必须流式**：`fopen` 循环 `fread(8192)`/`fwrite`，禁止 `file_get_contents`；`memory_limit` 保持 512M 但单片拼接不应超过数十 MB 峰值。
- **转码禁止同步**：`complete` 接口只入队并立即返回 `status=pending`，前端轮询或 WebSocket 更新状态；FFmpeg 用 `proc_open` + 超时控制，失败写 `fail_reason` 并支持重试。
- **`uploads` 目录禁止执行 PHP**：Nginx 层加 `location ~ \.php$ { deny all; }`，并补 `X-Content-Type-Options: nosniff`、`nosniff` 头；上传校验在现有"扩展名+大小"之上**补 `finfo` MIME 嗅探**，杜绝伪装扩展名。
- **OPcache `validate_timestamps=0` 后，发版必须 `php-fpm reload`**，否则代码不生效 —— 这是最容易踩的线上坑，需写进部署手册。
- **`think-queue` 引入前需过依赖审查**（维护度/许可/漏洞），并锁定 lockfile。
- **磁盘容量硬约束**：用户选择本地磁盘且单视频上限 1GB，50 个视频即逼近 50GB。必须给出容量测算表 + 转码降码率（1080p→720p 约省 40%）+ 回收站定期清理，并在后台展示已用容量。
- **带宽校验**：60 人同时播 2Mbps 视频 ≈ 120Mbps，需确认内网/出口带宽；若不足，后续再引入 CDN（配置已预留 `deploy.resource.mode/cdn` 开关）。
- **渐进式发布**：先在 Ubuntu 预发环境完成压测与回归（现有公告/门户/AI Skill 功能不得劣化），灰度切流，预写回滚步骤（Nginx 回切 + 数据库回滚脚本）。
- **压测验收口径**：60/80/100 三档并发，接口 P95 < 500ms、错误率 < 0.5%；视频场景单独压测（30 路并发播放），验证 PHP-FPM worker 不被占用（`pm.status_path` 观察 active processes）。

## 设计风格

延续 INUEIP 现有 Element Plus 企业级门户风格，采用 **Fluent Design** 视觉语言：柔和渐变、亚克力质感卡片、清晰分层阴影、克制的微交互。整体明亮专业，避免花哨；在视频/上传这类"重操作"区域用更强的层次与状态反馈降低焦虑感。

- **知识卡片瀑布区**：卡片含封面图（16:9，视频类叠加半透明播放三角 Icon 与时长角标）、标题（两行截断）、摘要、分类标签、浏览量与更新时间；hover 时封面轻微放大 + 卡片抬升阴影。
- **分页与空状态**：底部 Element Plus 分页；无数据时展示插画式空状态与引导文案。

### 2. 门户 · 知识详情页面

- **顶部导航栏**：含返回按钮与面包屑（知识库 / 分类 / 标题），右侧"收藏/分享"。
- **视频播放区**：顶部 16:9 播放器，圆角卡片包裹，深色底；自定义控制条（播放/暂停、进度条带缓冲态、倍速、全屏）；未就绪时显示"转码中"骨架屏与进度提示。
- **正文阅读区**：左侧可折叠目录锚点（跟随滚动高亮），右侧富文本正文；图片点击可放大预览（灯箱）。
- **底部信息栏**：作者、发布时间、浏览量、上下篇切换，以及相关推荐卡片横滑列表。

### 3. 后台 · 知识库管理页

- **顶部导航栏**：后台统一导航，右侧环境与账号信息。
- **分类树面板**：左侧树形分类，支持新增/重命名/拖拽排序/启停，右键菜单操作。
- **文章表格**：右侧表格含封面缩略图、标题、分类、状态标签（草稿灰/已发布绿/已下架橙）、浏览量、更新时间；顶部工具栏为搜索框 + 分类筛选 + 状态筛选 + "新建文章"主按钮。
- **操作列与统计条**：行内"编辑/上架下架/删除"（删除走二次确认）；页脚展示存储已用容量与视频转码队列状态。

### 4. 后台 · 文章编辑页

- **顶部导航栏**：面包屑返回 + 右侧"保存草稿 / 发布"双按钮（主次分明）。
- **基础信息区**：标题输入、分类选择、摘要输入、封面上传（拖拽上传 + 预览 + 裁剪）。
- **富文本编辑区**：复用 wangEditor，图片粘贴自动上传到知识库图床；工具栏精简为常用项。
- **视频上传区**：拖拽上传面板，展示文件名、大小、分片进度条、实时速度、暂停/继续/取消按钮；断点刷新后自动提示"发现未完成任务，是否续传"；四态标签（上传中/合并中/转码中/就绪）与转码预览。

## 响应式与交互

- 桌面优先（1280–1920px），≤1024px 时分类树折叠为抽屉；视频播放器宽度自适应并保持 16:9。
- 微交互：卡片 hover 上浮、按钮涟漪、进度条平滑过渡、骨架屏渐显；状态切换用 200–300ms 缓动，避免突兀。
- 上传类操作全程可中断可恢复，任何失败都在面板内联提示原因，不使用遮挡式弹窗打断。
