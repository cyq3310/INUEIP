## 1. 架构与端口规划

```
浏览器  →  Nginx(:80 / :443 / :8080)
             ├─ /            → 前端静态文件  frontend/dist
             ├─ /api/        → 反代 → 127.0.0.1:8000
             └─ /uploads/    → 反代 → 127.0.0.1:8000
                                   ↓
                        Nginx(127.0.0.1:8000) → PHP-FPM → backend/public/index.php
                                   ↓
                                 MySQL
```

| 端口 | 用途 | 是否对外 |
|---|---|---|
| 80 / 443 | 前端站点（有域名 + HTTPS） | 是 |
| 8080 | 前端站点（无域名临时方案） | 是 |
| 8000 | 后端 PHP-FPM 入口 | **否**，只监听 127.0.0.1 |
| 3306 | MySQL | 否 |

**关键设计**：前后端同域部署，前端通过同源 `/api` 访问后端，因此**不存在跨域问题**，后端无需 CORS 中间件（项目里也确实没有全局 CORS 中间件）。

## 2. 环境要求

| 软件 | 版本要求 | 说明 |
|---|---|---|
| PHP | ≥ 8.0（实测 8.5 可用） | `composer.json` 要求 `>=8.0.0` |
| PHP 扩展 | `zip` `mbstring` `pdo_mysql` `xml` `curl` `gd` `bcmath` `intl` | **`zip` 必须**，Skill 压缩包解析用 `ZipArchive`，缺失会报「服务端未安装 zip 扩展」 |
| Composer | 2.x | 用于安装 `vendor/` |
| Node.js | **≥ 18（推荐 20）** | Vite 5 要求；Node 12 会导致 `vue-tsc` 语法错误崩溃 |
| MySQL / MariaDB | 5.7+ / 10.3+ | 库名 `INUEIP`，`utf8mb4` |
| Nginx | 任意稳定版 | 反向代理 + 静态托管 |

### 版本兼容性核验结果（PHP 8.5）

`backend/composer.lock` 中的依赖均无上限约束：

| 依赖 | 版本 | PHP 约束 |
|---|---|---|
| topthink/framework | v8.1.4 | `>=8.0.0` |
| topthink/think-filesystem | v3.0.0 | `^8.2`（8.5 满足） |
| topthink/think-orm | v4.0.51 | `>=8.0.0` |
| ezyang/htmlpurifier | v4.19.0 | 明确支持到 `~8.5.0` |
| firebase/php-jwt | v7.1.0 | `^8.0` |

> ⚠️ PHP 8.4+ 会对「隐式可空参数」等写法抛 deprecation。生产环境 `APP_DEBUG=false` 不会外显，但日志可能增多，建议按第 4.3 节调整 `error_reporting`。

## 4. 部署步骤

### 4.1 安装基础环境

```bash
sudo apt update && sudo apt install -y software-properties-common curl gnupg

# PHP 8.5（Ubuntu 22.04 默认源没有，需 ondrej 源）
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update
sudo apt install -y nginx mysql-server \
  php8.5-fpm php8.5-cli php8.5-mysql php8.5-mbstring php8.5-xml \
  php8.5-curl php8.5-zip php8.5-gd php8.5-bcmath php8.5-intl \
  composer
```

#### 安装 Node 20（重点，容易踩坑）

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v && npm -v      # 应为 v20.x / 10.x
```

**常见坑 1：Node 版本过低（v12）**
Vite 5 需要 Node ≥ 18，Node 12 下 `vue-tsc` 会因不支持可选链 `?.` 直接 `SyntaxError` 崩溃：

```
SyntaxError: Unexpected token '.'
    at .../node_modules/@volar/typescript/lib/quickstart/runTsc.js:33
```

**常见坑 2：dpkg 文件冲突导致装不上**

```
dpkg: error processing archive nodejs_20.20.2-1nodesource1_amd64.deb
 trying to overwrite '/usr/include/node/common.gypi', which is also in package libnode-dev
```

解决：先移除旧开发包再安装

```bash
sudo apt-get remove -y libnode-dev libnode72
sudo apt-get install -y nodejs
```

若仍失败，强制覆盖：

```bash
sudo dpkg -i --force-overwrite /var/cache/apt/archives/nodejs_20.20.2-1nodesource1_amd64.deb
sudo apt-get -f install -y
```

### 4.4 创建 PHP-FPM 专用 pool（推荐）

代码在 `/home/ubuntu` 下，该目录默认 `750`，`www-data` 无法进入。让 PHP-FPM 直接以 `ubuntu` 身份运行可一次性解决所有权限冲突。

`/etc/php/8.5/fpm/pool.d/inueip.conf`：

```ini
[inueip]
user  = ubuntu
group = ubuntu

listen = /run/php/php8.5-fpm-inueip.sock
listen.owner = www-data
listen.group = www-data
listen.mode  = 0660

pm = dynamic
pm.max_children = 20
pm.start_servers = 4
pm.min_spare_servers = 2
pm.max_spare_servers = 8

php_admin_value[error_log] = /home/ubuntu/INUGAME/INUEIP/backend/runtime/php-fpm-error.log
php_admin_flag[log_errors] = on
```

```bash
sudo php-fpm8.5 -t
sudo systemctl restart php8.5-fpm
ls /run/php/                     # 确认 php8.5-fpm-inueip.sock 存在
```

> 若不使用专用 pool，则使用默认 socket `/run/php/php8.5-fpm.sock`，但必须保证 `www-data` 对项目目录有读权限、对 `runtime` 与 `uploads` 有写权限。


构建产物：`frontend/dist/`（`index.html` + `assets/`）

#### 2核2G 小内存机器的构建建议

先加 Swap（**重启后需重新挂载，建议写入 fstab**）：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
grep -q '/swapfile' /etc/fstab || echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -m
```

构建时跳过 TS 类型检查、限制内存，更稳更快：

```bash
export NODE_OPTIONS=--max-old-space-size=1536
npx vite build
```

> 构建输出 `✓ 3452 modules transformed` → `rendering chunks (32)...` 属正常阶段，2核机器需 2~5 分钟，**不要中断**。
> 判断是否卡死：另开 SSH 窗口执行 `top`，CPU 接近 100% 即为正常运行；CPU 0% 则 `pkill -9 -f vite` 后重来。
> 更优做法：在本地构建好，仅把 `dist/` 上传到服务器。

### 4.10 配置 Nginx

`/etc/nginx/sites-available/eip.conf`：

```nginx
# ---------- 后端（仅本机访问） ----------
server {
    listen 127.0.0.1:8000;
    server_name 127.0.0.1;

    root /home/ubuntu/INUGAME/INUEIP/backend/public;
    index index.php;

    client_max_body_size 64m;      # 必须！默认 1m 会导致上传 413

    location / {
        if (!-e $request_filename) {
            rewrite ^(.*)$ /index.php?s=/$1 last;
        }
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.5-fpm-inueip.sock;
        fastcgi_index index.php;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_read_timeout 60s;
    }
}

# ---------- 前端站点 ----------
server {
    listen 8080 default_server;     # 有域名+HTTPS 时改为 listen 443 ssl http2;
    server_name _;                  # 有域名时改为你的域名

    root /home/ubuntu/INUGAME/INUEIP/frontend/dist;
    index index.html;

    client_max_body_size 64m;
    client_body_timeout 120s;
    proxy_read_timeout  120s;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location ^~ /uploads/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        expires 7d;
    }
}
```

启用配置：

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/eip.conf /etc/nginx/sites-enabled/eip.conf
sudo nginx -t && sudo systemctl start nginx
sudo systemctl enable nginx
```

> `nginx -t` 只校验语法，**不检测端口占用**。端口被占时表现为启动失败：
> `nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Unknown error)`

## 5. 生产配置详解（myconfig.php）

路径：`backend/config/myconfig.php`

### 5.1 必须修改的项

| 配置键 | 生产值示例 | 说明 |
|---|---|---|
| `deploy.env` | `production` | 环境标识 |
| `deploy.api.scheme/host/port` | `http` / 你的IP或域名 / 端口 | 后端对外地址 |
| `deploy.api.base_url` | 留空 | **留空则前端按同源 `/api` 访问**，最省事 |
| `deploy.web.base_url` | `http://IP:8080` | 前端根地址 |
| `deploy.cors.allow_origin` | 与 `web.base_url` **完全一致** | 不一致会导致跨域拦截；生产禁止填 `*` |
| `database.username/password` | 真实库账号密码 | 与 `.env` 保持一致 |
| `jwt.secret` | 64 位随机串 | **必须与 `.env` 的 `JWT_SECRET` 完全一致**，否则登录 401 |
| `site.icp` | 备案号 | 无则留空 |
| `skill.use_mock` | `false` | 走真实接口 |

## 6. 权限模型

| 目录 | 属主 | 权限 | 原因 |
|---|---|---|---|
| `backend/runtime/` | ubuntu（或 www-data） | 775 / 664 | 文件缓存、日志写入；登录失败锁定依赖此缓存 |
| `backend/public/uploads/` | 同上 | 775 / 664 | 公告图、门户背景图、Skill 包 |
| `frontend/dist/` | ubuntu | 至少 a+rX | Nginx 需读取静态文件 |
| `/home/ubuntu`、`INUGAME`、`INUEIP` | ubuntu | 需 `g+x` | 否则 Nginx/PHP-FPM 无法进入目录 |

> **重要**：回收站（`uploads/trash`）与正式目录必须位于同一文件系统，否则 `rename()` 退化为「复制+删除」，失去原子性。默认配置下二者同在 `uploads/` 下，满足要求。

## 7. 有域名时的 HTTPS 配置

Let's Encrypt **不支持为纯 IP 签发证书**，必须有域名。

### 步骤

1. 先用 HTTP 版配置（80 端口）启动，确保域名已解析到本机、80 端口可访问：

```bash
dig +short eip.example.com
curl -4 ifconfig.me
```

2. 签发证书：

```bash
sudo apt install -y certbot
sudo certbot certonly --webroot \
  -w /home/ubuntu/INUGAME/INUEIP/frontend/dist \
  -d eip.example.com
```

3. 再把前端 server 块改为 HTTPS：

```nginx
server {
    listen 443 ssl http2;
    server_name eip.example.com;

    ssl_certificate     /etc/letsencrypt/live/eip.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/eip.example.com/privkey.pem;

    root /home/ubuntu/INUGAME/INUEIP/frontend/dist;
    index index.html;
    client_max_body_size 64m;

    location / { try_files $uri $uri/ /index.html; }

    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location ^~ /uploads/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        expires 7d;
    }
}

server {
    listen 80;
    server_name eip.example.com;
    return 301 https://$host$request_uri;
}
```

4. 同步修改 `myconfig.php`（见 5.3）并执行 `php think clear`。

> ⚠️ **顺序很重要**：必须先有证书文件，Nginx 才能加载 443 配置。否则启动报 `cannot load certificate ... BIO_new_file() failed`。
> ⚠️ 境内服务器对外提供 Web 服务需备案，未备案时 80/443 可能被拦截。

## 9. 日常更新发布流程

```bash
cd /home/ubuntu/INUGAME/INUEIP

# 1. 拉代码
git pull origin main

# 2. 后端依赖（有更新时）
cd backend && composer install --no-dev --optimize-autoloader

# 3. 执行新迁移（有 migration 时）
php think migrate:run

# 4. 清缓存
php think clear

# 5. 前端重新构建
cd ../frontend && npm ci && npm run build

# 6. 前端静态文件无需 reload nginx；改了 nginx 配置才需要
# sudo nginx -t && sudo systemctl reload nginx
```

**回滚**：`git checkout <上一个commit>` 后重复 2~5 步；数据库迁移需按 migration 的 `down` 手工处理，建议回滚前先做数据库备份。

## 12. 故障排查手册

### 12.1 Nginx 启动失败

| 报错 | 原因 | 处理 |
|---|---|---|
| `cannot load certificate ... BIO_new_file() failed` | 443 配置引用了不存在的证书 | 先签证书（第 7 节），或暂时删除 443 server 块 |
| `unexpected ";" in ...:24` | 配置里有多余分号（如 `listen 80 default_server; ;`） | 修正为 `listen 80 default_server;`；注意从聊天窗口复制易带入全角符号 |
| `a duplicate default server for 0.0.0.0:80` | 多个 server 块声明了 `default_server` | 删除 `/etc/nginx/sites-enabled/default`，保证每个端口只有一个 `default_server` |
| `bind() to 0.0.0.0:80 failed (98)` | 80 端口被占用 | `sudo ss -tlnp 'sport = :80'` 查占用者；停掉 Apache（`systemctl stop apache2`）或改端口 |
| `nginx.service is not active, cannot reload` | 服务未启动 | `sudo systemctl start nginx`（`nginx -t` 通过不代表服务在运行） |

### 12.2 访问异常

| 现象 | 原因 | 处理 |
|---|---|---|
| 前端 500，日志 `rewrite or internal redirection cycle while internally redirecting to "/index.html"` | `dist/index.html` 不存在或 Nginx 读不到 | ① 执行 `npm run build`；② `sudo chmod g+x /home/ubuntu /home/ubuntu/INUGAME /home/ubuntu/INUEIP` |
| 前端 403 | 目录无执行/读权限 | `chmod g+x` 父目录 + `chmod -R a+rX dist` |
| `/api/*` 502 | FPM socket 路径错误或 PHP-FPM 未启动 | `ls /run/php/` 核对 socket 名；`systemctl restart php8.5-fpm` |
| `/api/config` 404 | Nginx 未匹配到 `/api/` 反代，或后端 rewrite 失效 | 检查 `location ^~ /api/` 与后端 `rewrite ... /index.php?s=/$1` |
| 登录一直 401 | `myconfig.jwt.secret` 与 `.env` 的 `JWT_SECRET` 不一致 | 改成完全一致后 `php think clear` |
| 接口跨域被拦 | `cors.allow_origin` 与 `deploy.web.base_url` 不一致 | 改成完全一致 |
| 页面露出堆栈/警告 | `APP_DEBUG` 未关闭或 PHP `display_errors=On` | 均设为关闭 |
| 上传报 413 | Nginx `client_max_body_size` 或 PHP `upload_max_filesize` 过小 | 两处都设为 64M |
| 「未收到压缩包」/「服务端未安装 zip 扩展」 | 缺 `php8.5-zip` 或 `post_max_size` 过小 | `sudo apt install php8.5-zip`；提高 `post_max_size` |
| 登录失败锁定不生效 / 上传失败 | `runtime`、`uploads` 不可写 | 按第 6 节修正属主与权限 |
| 本机 curl 正常、外网不通 | 云安全组未放行端口 | 控制台安全组放行对应 TCP 端口 |

### 12.3 前端构建失败

| 报错 | 原因 | 处理 |
|---|---|---|
| `SyntaxError: Unexpected token '.'` in `@volar/typescript` | Node 版本 < 14（如 v12） | 升级 Node 20（第 4.1 节） |
| `trying to overwrite '/usr/include/node/common.gypi'` | `libnode-dev` 冲突 | `sudo apt-get remove -y libnode-dev libnode72` |
| `JavaScript heap out of memory` | 内存不足 | 加 Swap + `NODE_OPTIONS=--max-old-space-size=1536` |
| `vue-tsc` 报 TS 类型错误 | 类型检查不通过 | 临时用 `npx vite build` 跳过类型检查 |
| 构建长时间无输出 | 2核机器正常耗时 | 另开窗口 `top` 确认 CPU 占用，耐心等待 |
